The github-issues skill is not installed, so follow GitHub's issue best practice.

- Pick one template by the kind of request.
  A bug is a Bug report with the sections Description, Steps to reproduce, Expected behaviour and Actual behaviour.
  A feature is a Feature request with the sections Summary, Motivation, Proposed solution and Acceptance criteria.
  Anything else is a Task with the sections Objective, Details and Checklist.
- Keep the title under 72 characters and make it specific.
- Do not repeat the type in the title when a type is set.
- Write acceptance criteria as checkboxes, each one observable.
- When a similar issue is the same subject, link it in the body with "Related to #<number>".
- Do not include credentials, tokens or private data.
